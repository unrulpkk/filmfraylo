# 小说连续性导演

把小说转分镜过程中容易遗忘的设定保存成可复用资产，并用代码编译提示词。适用于长篇小说跨章节、跨对话续作，以及同一地点反复返场。插件调用现有 FilmFraylo Agent 的理解能力，不额外部署大模型或服务。

## 安装与开始使用

在本包目录执行 `bun run build`，产物为仓库 `build/tools/novelDirector.tool.js`。在 FilmFraylo「设置 → 插件市场」安装该文件并启用，下一条 Agent 消息生效。开发环境可用 `NODE_ENV=dev` 构建同步至仓库 `data/tools/`。不需要替换服务端、节点插件或默认分镜团队。

同时启用工作区文件、画布、媒体生成插件，配置自己的图片、音色和视频模型。将小说 UTF-8 TXT 放进 FilmFraylo 当前工作区，向 Agent 发送：

> 使用小说连续性导演插件处理《司藤》的第零章和第一章。先建立固定角色、服装、音色、地点空间母版和场景状态，补充设计与原文事实分开记。人物和场景优先使用 Z-Image-Base，音色使用 Qwen3 音色设计，分镜面向 MiniMax-H3。先完成资产与分镜方案并搭建画布，视频暂不生成。每次返回同一地点复用原场景 ID 和参考图，不重新设计空间。

插件的包级规则会注入已加载该工具的 Agent。工具名为 `novelDirector`。如果使用工具白名单或只读分镜团队，需允许此工具及画布/媒体工具，或直接在主 Agent 中使用。插件自身不调用生成接口；是否生成素材由用户任务和宿主已有工具决定。

## 为什么需要这层流程

用户提供的《司藤》执行记录显示，42 段视频只接入角色图与音色，没有独立场景资产，返场没有稳定空间参照。角色提示词把头部与三面全身压到一张 16:9 图里；部分服装含“冲锋衣／大衣”这类未定选项。这里能确认的是制作流程的缺口，尚不能从文字记录判断真实图片的质量，也没有原先42条完整分镜提示词可供逐镜评价。

本插件将角色肖像和服装照分开；为未给定的长相、色彩等保留明确的统一设计，不冒充原文。场景拆为固定地点与可变状态，按资产 ID 持久引用，不依赖聊天上下文记忆。

## 资产和制作状态

| 类型 | 保存内容 | 依赖 |
| --- | --- | --- |
| character | 脸、发型、年龄感、体型；单张肖像 | 无 |
| appearance | 固定服装、鞋、饰品；单张全身照 | character |
| voice | 音域、音质、口音；试听文本 | character |
| location | 世界方位、门窗/路口、距离、地标、材质；无人空间母版 | 无 |
| sceneState | 昼夜、天气、光线、道具/损坏状态；无人状态参考图 | location |

例如同一条上海弄堂的夜景与日景是一个 location 的两个 sceneState。固定布局不变；再次回到相同夜景直接引用之前的 state。视频使用状态图作为场景参考，避免将中性母版与夜景同时输入引发冲突。服装图和场景状态图绑定前，必须先绑定父级肖像或空间母版。

`evidence` 是原文片段及字符范围，保存时核验逐字相等；`design` 是明确标注的补充设计；`locks` 是编译时逐字复用的固定锚点。模型仍可能画错，用户或 Agent 需要实际查看候选结果；登记文件不能替代视觉审核。Z-Image-Base 若不支持参考输入，父级图片只用于核对，不能宣称多次文生图已保证同脸。

项目保存为当前工作区 `novelDirector/<projectId>.json`，内含冻结原文、资产与镜头。`revision` 防止旧对话覆盖新进度，宿主文件层负责原子保存。原文最多32 MB/1600万 UTF-16 单元，最多1万资产、2万镜；更长作品按卷拆分。仅支持单个 FilmFraylo 服务进程，不能用多个服务同时写同一项目。不要用文本编辑器直接修改项目 JSON 或替换已绑定的素材文件。

资产设定与引用登记后不可原地覆盖。更换设计或文件需创建新 ID 和可区分的版本名称，再用 `saveShots` 修订引用；无变化直接复用已有 ID。原文件摘要变更会阻塞视频准备。

## 工具操作

| action | 用途 |
| --- | --- |
| create | 从 sourcePath 冻结 UTF-8 原文，保存 style、maxShotSeconds（默认12）、speechCharsPerSecond（默认4） |
| inspect | 返回 revision、数量、最近分镜、未覆盖原文区间 |
| source | 按 offset/length 读原文；坐标为零起始 UTF-16 单元，end 不包含，换行不规范化 |
| addAssets | 每批最多8个资产，查重并核对 evidence；携带 revision |
| readAssets | 按 kind/ids 筛选与分页，返回地点/角色最近已登记状态 |
| assetPrompt | 返回 Z-Image 单幅提示词或 Qwen3 的 prompt/voicePrompt；模型 ID 仍需实时查询 |
| bindReference | 绑定已存在的工作区图片或音频，校验格式并记录 SHA-256；携带 revision |
| saveShots | 每批最多8镜，按 ID 修订或追加；携带 revision，整批失败不写盘 |
| readShots | 分页读分镜，可按 ids 筛选 |
| compile | 分页编译最终视频提示词、参考输入顺序、参数建议、ready/blockers |
| export | 新建 `<projectId>Export<revision>.json` 审阅清单，同名不覆盖；携带 revision |

分页默认4项、最多8项，使用 nextOffset 续读。创建后 revision=0，每次修改加1；查询/编译/导出不增加 revision。修订镜头保持原序，新 ID 追加到末尾。

镜头必须包含 source、locationId、sceneStateId、cast、framing、camera、axis、entryState、exitState、beats、dialogue、sound。beats 必须连续覆盖整个时长。对白只能来自本镜原文，必须指定实际说话者及其 voiceId；默认以每秒4个非标点字符加0.4秒停顿估算预算。这是保守的中文对白预算，不是语音对齐测量；其他语言需自行调整并试听。

返场对照该地点最近一镜的退出状态；角色对照最近一次出场。未说明的状态、衣着、音色变化会拒绝保存；有依据的变化用 continuityNote 解释。该说明的合理性仍需导演审阅，程序不理解剧情真假。source 覆盖率只说明引用区间覆盖，不证明事件无遗漏。

MiniMax H3 编译清单限制9张图片、3段音频、总计12个参考。每位可见人物占肖像与服装两图，场景占一图；多人镜头超限需拆镜。仅有台词者带音色。ready 表示机械校验、文件存在和摘要检查通过，不代表模型支持已核实或视频效果已验证。调用前仍需用 listMediaModels 核对实际 provider/model/模式/时长/分辨率。

## 画布衔接与边界

插件给出稳定节点标签，Agent 用现有画布工具查找或创建节点，按“文本 → 生成节点”连接，并逐批核对实际端口与参考顺序。它不直接写画布 JSON，也不自动生成或自动排布整张画布。能否完整遵循这一流程取决于主 Agent；本版本对资产引用、对白、时长、连续状态和参考文件的检查是代码级约束，分镜艺术质量与视觉一致性仍需要实际模型结果来验收。

中断后重新 inspect/readAssets/readShots，然后从未完成处继续。导出清单不带整本原文，但包含引用片段、素材路径和提示词，分享前按需要处理。
