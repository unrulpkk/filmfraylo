日期：2026-10-26。此次将 Toonflow 基线从 `2c7fb257affb65777110fe4c6e60cd3c09187d9b` 升级到 `30139c931e80476caa718b31684b86383c6e83ce`，采用独立工作树三方合并。升级代码已合入 GitHub `main`；此次正式发布版本为 2.0.5，由 `v2.0.5` 标签触发发布构建。初次本地验证包使用 2.0.3，不能与先前发布的同名版本混淆。

| 20 份上游译版介绍 | 保留上游参考原文，文档目录明确标注其适用范围。FilmFraylo 产品说明继续以仓库根 README 和 `docs/filmFraylo.md` 为准，避免把上游社区和服务冒充成本产品入口。 |

| 桌面与构建 | 合入 Windows 兼容启动、WebView2 安装修复、文档解析原生依赖和麦克风声明。更新器与 C# 助手校验 FilmFraylo 身份，便携入口转交兼容启动器。根 Skill、发布渠道与用户数据目录保持 FilmFraylo 约定。 |

产品身份、默认网关、主题色、支持电话和开放能力集中在 `packages/product/product.json`；`@toonflow/product` 提供运行时入口和品牌模板处理。Web 资源集中在 `apps/web/src/lib/product.ts`。C# 产品身份由桌面构建脚本从同一配置生成。媒体提供方源码需被独立加载，因此其自包含网关默认值继续留在适配器中，主机初始化及模型列表同步读取产品配置。

内部包名、节点 ID、画布字段、`toonflow://` 和 MCP 通信字段保留兼容名称。MIT 许可与上游作者归属保留。没有把冲突文件整批选择为本地版或上游版。

## 实际完成的验证

- Bun 1.4.3 冻结锁文件安装通过；TypeScript 统一到与 Vue 检查工具兼容的 6.0.3。Vite 使用 Node.js 24.19.0。
- 全仓现有 `typecheck` 通过，覆盖 Web、Server、桌面、移动端、节点、工具、扩展和产品配置包。
- 重新生成服务端路由，完成 Web、Server、MCP、全部节点、工具及扩展构建。
- Windows 桌面完整构建成功，便携 ZIP 与 SHA256 文件生成；包内身份为 `local.filmfraylo.desktop`，版本 2.0.3，包含 FilmFraylo Logo、启动图和兼容启动器。
- 使用独立数据目录启动构建后的 Server，页面响应 HTTP 200。默认文本提供方为 safillu，媒体列表包含 6 个 safillu 模型。
- 设置接口保存、重读正常，自定义字段及网关地址保留；非法设置结构返回 HTTP 400。
- 空工作区的音色设计请求在缺少 Key 时返回业务错误 400，工作区未产生素材；非开放媒体提供方请求返回 HTTP 400。
- 节点接口加载 10 个节点，无加载错误；包括新增 `frameAnalysisNode` 和原有预置 `webEpisodeEditorProNode`。
- 浏览器验证首次配置入口、FilmFraylo 标题与标识、中英文版权文案；缺少 Key 时直接访问首页仍返回首次配置页。
- 翻译入口实际输出 FilmFraylo 文案，传入的用户原文参数保持原样。
- 修复 hoisted 依赖布局的许可收集和 Intel Mac 原生 SDK 准备步骤后，主分支的 Windows x64、macOS Intel / Apple Silicon 桌面及 Web 包均已通过 [GitHub Actions 构建](https://github.com/unrulpkk/filmfraylo/actions/runs/40322965648)。正式发行包使用 2.0.5 版本号重新构建。

验证只使用本次独立数据目录，未读取或覆盖真实项目和密钥。没有真实 API Key，未执行付费图片、视频、配音生成；未完成已有真实项目的完整创作回归。macOS、移动端实机、麦克风权限、外部 MCP 服务连接和更新安装/回滚实机流程仍需按发行平台验收。Windows 构建和安装包生成不等同于这些功能已通过实机验收。
